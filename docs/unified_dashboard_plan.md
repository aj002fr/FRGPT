## Global non‑negotiable contracts (apply to all panels)

### Performance contract
- Everything expensive is **precomputed once** (batch).
- Everything interactive is **slice + recombine** from precomputed data.
- Live data is an **overlay**, never a dependency.

### No dynamic OHLC contract
- There is **no request‑time candle aggregation**.
- `/api/candlestick` accepts only **precomputed** resolutions (e.g., `1m`, `5m`).

### Time ordering contract (all time‑series)
Before doing **anything** with time‑series data (price paths, candlesticks, resampling, returns/stats, any derived fields):
- Data must be **strictly time‑ordered ascending** by timestamp.

Enforcement:
- Always `ORDER BY ts` in any query/batch job that materializes time‑series.
- On read: assert monotonic; if violated, **sort** and log (L1 builds should fail on violations).
- Never assume DB/file row order is correct.

### Conversions contract
- Treasury **decimal ↔ ticks ↔ bps** conversions (and display formatting) must use `rules/treasury_price_conversion.py` only.

### Outlier toggle contract (any distribution)
- Any “exclude outliers” toggle must apply to **both**:
  - plotted distribution
  - stats panel values
- The outlier definition must be explicit and consistent (see Appendix D).

### Componentization contract (testability)
Each major panel is implemented as a **separate component/module** with:
- Explicit **inputs** and **outputs** (callbacks/events)
- No hidden global reads
- Deterministic unit tests using **small synthetic fixtures**
- API‑driven smoke tests that exercise real flow (NFP default)

### Shared panels contract (reuse without divergence)
Shared panels must not be duplicated.
- **Single canonical implementation** per shared panel.
- Tabs use **thin adapters** (map tab state → panel inputs).
- Changes are made via explicit inputs/flags or new panel (only if truly different).
- Shared helpers contain: ordering assertions, normalization, bucketing, binning, outlier filtering, conversions.
- Shared tests:
  - canonical panel unit tests
  - “context tests” mounting the same panel in each tab adapter

## System design (storage, APIs, state, wiring, caching)

### Tech stack assumption (keep consistent with existing standalone dashboards)
- UI is **static HTML + JS** generated by Python and uses **Plotly** for charts.
- Data loads via API endpoints only (no large embedded datasets).

### What is stored where
- **L0 (canonical)**: Postgres `public.ohlcv_1m`
  - Batch/backfill only (not interactive hot path).
- **Meta**: `workspace/economic_events.db` (SQLite)
  - Event calendar, timestamps, annotations.
- **L1 (serving store)**: local precomputed files (memory‑mappable, per event day)
  - `data/event_features/{EVENT_TYPE}/{YYYY-MM-DD}.meta.json`
  - `data/event_features/{EVENT_TYPE}/{YYYY-MM-DD}.price_1m.arrow`
  - `data/event_features/{EVENT_TYPE}/{YYYY-MM-DD}.price_5m.arrow`
  - optional: `data/event_features/{EVENT_TYPE}/{YYYY-MM-DD}.stats.arrow`
- **L2 (hot cache)**: in‑process, derived results cache (safe to drop)
- **L3 (live overlay)**: in‑memory live last price/extrema (optional; `/api/live`)

Exact L1 schemas: Appendix E.

### Prerequisite scripts (builders + preprocessing) required for the dashboard
These scripts are required so the interactive dashboard can serve **only** from L1 (plus L2 caches), with no heavy DB scans or request‑time aggregation.

#### 1) Metadata / calendar builder
`scripts/build_event_calendar_sqlite.py`
- **Purpose**: ensure `workspace/economic_events.db` contains:
  - event calendar for NFP/CPI/PPI/JOLTS
  - event timestamps (ET + UTC epoch) and annotations
  - component definitions snapshot (optional)
- **Inputs**: existing calendar sources used in this repo (or curated CSV/JSON)
- **Outputs**: updated `workspace/economic_events.db`
- **When to run**: on calendar updates; also as part of full backfill.

#### 2) L1 event features builder (core)
`scripts/build_l1_event_features.py`
- **Purpose**: build the per‑event files listed in `data/event_features/...` from L0 + Meta.
- **Inputs**:
  - Postgres `public.ohlcv_1m` (or other canonical raw store for the instrument)
  - `workspace/economic_events.db` for event times and dates
  - event config mapping (event time, default windows, supported components)
- **Outputs (per event day)**:
  - `{YYYY-MM-DD}.meta.json`
  - `{YYYY-MM-DD}.price_1m.arrow`
  - `{YYYY-MM-DD}.price_5m.arrow`
- **Preprocessing performed (must be deterministic)**:
  - enforce **time ordering** before writing (fail build on violations)
  - filter/flag bad ticks if applicable; set `validation.bad_tick_filtered`
  - generate **precomputed** 1m/5m candles (no dynamic OHLC at runtime)
  - write `event_ts_utc` into meta and ensure UTC epoch consistency (Appendix B)
- **CLI shape (example)**:
  - `--event-type NFP --start-date YYYY-MM-DD --end-date YYYY-MM-DD`
  - `--rebuild` / `--incremental`

#### 3) Derived stats / distributions precompute (optional but recommended for “No filters” mode)
`scripts/build_l1_event_stats.py`
- **Purpose**: precompute `stats.arrow` so envelope lines and distribution drilldowns are instant even for large samples.
- **Inputs**: the L1 `price_*.arrow` files + window presets
- **Outputs**: `{YYYY-MM-DD}.stats.arrow` (optional)
- **Notes**:
  - must match Appendix D formulas exactly
  - bins must be 0‑aligned per Appendix D if histogram summaries are stored

#### 4) Validation + audit tool (CI + dev)
`scripts/validate_l1_event_features.py`
- **Purpose**: assert the global contracts over the built L1 store:
  - strictly increasing timestamps
  - supported resolutions only
  - meta.json required keys present
  - candle OHLC consistency (no NaNs; open/high/low/close sane)
  - schema compatibility with Appendix E
- **Outputs**: exit non‑zero on violation; optionally a report JSON.
- **When to run**: CI gate + before deploying/building dashboards.

#### 5) Incremental updater (daily job)
`scripts/update_event_features_incremental.py`
- **Purpose**: keep L1 current without full rebuild.
- **Behavior**:
  - detect new events (from SQLite calendar)
  - build missing L1 days only
  - bump `build_version` and ensure caches are invalidated by version key

#### 6) Fixture generator for tests (small synthetic data)
`scripts/generate_synthetic_event_fixtures.py`
- **Purpose**: generate tiny deterministic fixtures for unit tests (paths, candles, returns) without embedding real datasets.
- **Outputs**: small JSON fixtures under `tests/fixtures/` (or equivalent).

Implementation note:
- The exact filenames above are the proposed canonical locations. If the repo already contains equivalent builders, rename/alias them to these entry points so the plan matches reality.

### What is embedded vs fetched

- HTML/JS includes only:
  - static UI shell + CSS

### State model (single canonical state object per tab)
Each tab adapter builds panel inputs from a **single canonical state object** (no duplicated state per panel).

Recommended Event Analysis state:
- `event_type`: one of NFP/CPI/PPI
- `mode`: `pre` | `post`
- `pre_start_hhmm`, `post_end_hhmm`
- `start_year`
- `selected_components`: list[str]
- `component_inputs`: per‑component user inputs (std devs; actual/consensus where applicable)
- `no_filters_all_events`: bool
- `boxplot_y_axis`: `multiplier` | `bps`
- `boxplot_x_axis`: `headline` | `headline_plus_components`
- `include_outliers`: bool (where applicable)

### Wiring map (Event Analysis)
InputControlsPanel
  → mutates EventAnalysisState
  → triggers refresh of:
    - BoxplotPanel
    - PricePathsPanel
    - DistributionExplorerPanel

PricePathsPanel
  → `onTraceClick(date)`:
    - updates SelectedEvent state
    - enables CandlestickPanel
    - sync‑highlights DistributionExplorer selection

DistributionExplorerPanel
  → `onBinClick(bin_id)` shows contributing days
  → `onDaySelected(date)` sync‑selects the same date in PricePathsPanel and enables CandlestickPanel

### Caching strategy (minimal, consistent)
- Cache `/api/events` per `(event_type, start_year)` (client or server; choose one policy).
- Cache `/api/event_details` per `(event_type, date)` (lazy fetch + memoize).
- Cache `/api/candlestick` per `(event_type, date, res, days)` (memoize).
- Never cache raw unsorted time‑series; ordering contract applies at read.

### Fetch concurrency contract
- Each panel fetch includes a `request_id` (or uses AbortController in JS).
- On state change, abort in-flight requests for that panel.
- Never render stale responses (compare request_id before updating UI).
- Input Controls uses **debounced auto-apply (300ms)** for text inputs; immediate for selectors/toggles.
- If a fetch fails, panel shows error state; user can retry without affecting other panels.

### Live polling contract (Databento-backed)
- **Polling interval**: 3 seconds (configurable via `/api/config` → `live_poll_interval_ms`).
- **Staleness threshold**: 10 seconds since last successful update → show "stale" indicator.
- **Failure handling**: after 3 consecutive failures → show "disconnected" status + last known values with timestamp.
- **Source**: Databento streaming API (see `scripts/databento_zn_live.py`) writes to SQLite; `/api/live` reads from SQLite (and may keep a small in-process cache).
- **WebSocket**: optional enhancement for sub-second updates (not MVP; polling is sufficient).
- Live failures never block historical panels per Appendix G.

### Databento ingestion contract (live overlay)
- **Dataset**: CME Globex futures dataset (example in repo uses `GLBX.MDP3`).
- **Symbology**: Use either:
  - continuous front contract (e.g., `ZN.c.0`) for live overlay continuity, or
  - specific contract (e.g., `ZNH5`) when exact contract alignment is required.
- **Schemas**:
  - **Trades** schema for last-trade price/time (minimum required for overlay).
  - Optional **MBP-1** for best bid/ask (if UI needs spread / mid).
- **Timestamps**: Store `ts_event` in UTC nanoseconds (or convert deterministically to UTC epoch ms/sec for API) and retain the original precision in the SQLite store.
- **Resilience**: On startup, optionally replay the last 1h into SQLite before switching to live stream to avoid gaps; implement reconnect with exponential backoff.
- **Configuration**: `DATABENTO_API_KEY` must be present in runtime environment for the streamer process.

### Steps to reach the ideal "snappy" storage state
1. Define L1 schemas + validation flags (Appendix E).
2. Build/extend L1 builders for NFP/CPI/PPI; fail builds on contract violations.
3. Rewire endpoints to serve from L1 only (no Postgres on interactive path).
4. Add L2 derived caches keyed by query shape + build version.
5. Add NFP end‑to‑end smoke tests using normal API‑driven flow.

### State persistence contract (optional for MVP)
- **URL hash**: Tab selection + `event_type` serialized to URL hash for bookmarking/sharing.
  - Format: `#tab=event_analysis&event_type=NFP&mode=post`
- **localStorage**: Full state optionally persisted to `localStorage` keyed by `dashboard_state_v1`.
  - Includes: `event_type`, `mode`, `start_year`, `selected_components`, `pre_start_hhmm`, `post_end_hhmm`
- **Browser navigation**: Back/forward buttons update tab selection from URL hash.
- **Deep linking**: External links with hash params restore dashboard state on load.

### Panel: Pre/Post Boxplot
**Purpose**
- Boxplot summary with configurable axes:
  - **Y axis**: B/E multiplier or bps move
  - **X axis**: headline‑only or headline + selected components bucketization

**Inputs**
- `/api/events` lightweight list + required derived values
- current window + mode + component selections

**User interactions**
- Toggle: **No filters (All events)**
  - When enabled: disable bucketization; compute stats/plots over all events in sample
- Y axis selector: multiplier vs bps
- X axis selector: headline vs headline + components
- Bucket width changes (when bucketized)
- Include outliers toggle (when applicable)

**Bucketization rules (to remove ambiguity)**
- **Headline-only** (`boxplot_x_axis=headline`): bucket by **headline z-score** (Appendix D) into fixed-width σ bins.
  - Default bucket width: `0.5σ`, aligned so 0 is a boundary.
- **Headline + components** (`boxplot_x_axis=headline_plus_components`): bucket by **categorical Low/Medium/High (L/M/H)** for headline and each selected component:
  - Each dimension ∈ `{Low, Medium, High}` based on z-score thresholds (Appendix D).
  - Bucket key is the tuple: `(headline_LMH, comp1_LMH, comp2_LMH, ...)`.
  - **All possible combinations** are valid buckets (e.g., with 2 components there are \(3^3 = 27\) buckets including headline).
  - Labels must render as: `H:High | UER:Low | ...`.
  - Guardrail: enforce `max_components_in_combo` (default 2; configurable per event type). If user selects more than allowed, UI must either:
    - force headline-only mode, or
    - use headline + first N components deterministically (document which; default: first N in selection order).

**Rules/contracts used**
- Outlier toggle contract (Appendix D + global).
- Small sample warning: `⚠️ n<3`.

**Outputs**
- `onBucketSelection(bucket_id)` (disabled/unused if No‑filters is enabled)

**Edge cases**
- No events after filtering → empty state (Appendix G)

**Tests**
- Unit: “No filters” disables bucketization and uses full sample deterministically
- Unit: y‑axis selector switches value family deterministically
- Unit: x‑axis selector switches bucketization deterministically
- Unit: outlier toggle changes included sample and box stats deterministically

**Acceptance criteria (panel‑level)**
- Supports No‑filters + bucketized modes without errors; axes toggles behave deterministically.

- mean
- percentile where 0 bps lies (can display as “rally rate”)
- expected rally
- expected selloff
- P5 and P95
- min and max

**Outputs**
- `onDaySelected(date)` → Price Paths + Candlestick

**Edge cases**
- N too small → still render; label N; avoid misleading KDE

**Tests**
- Unit: bin edges always include 0 as boundary (property test over random min/max)
- Unit: outlier toggle changes both distribution sample and stats
- Unit: click‑bin drilldown returns correct contributing dates deterministically

**Acceptance criteria (panel‑level)**

## Testing strategy

### Panel unit tests
- Every panel has mocked‑data unit tests validating:
  - pure computations
  - callback emissions
  - toggles/filters
  - ordering guards

### Composition tests (dashboard‑level smoke)

### Appendix D — Core formulas/algorithms (exact)
All conversions must use `rules/treasury_price_conversion.py`.

#### Time ordering
- Any time‑series must be strictly increasing by timestamp before use.
- If unsorted at read: sort + log; L1 builds should fail on violations.

#### Normalization (paths → bps)
Given decimal price series and reference anchor price:
- `move_bps[t] = points_to_bps(price_dec[t] - ref_price_dec)`

Note: Decimal price differences are already in "points" (1 point = 8 bps for Treasury futures). Use `points_to_bps()` from `rules/treasury_price_conversion.py`.

#### Window move (scalar)
For a window \([t_0, t_1]\):
- `window_move_bps = points_to_bps(price_dec[t1] - price_dec[t0])`

#### B/E multiplier (for Boxplot Y-axis = multiplier)
Given:
- `window_move_bps` (above)
- `fwd_bps > 0` (user input; comes from Input Controls and/or Live Stats)
Compute:
- `be_multiplier = window_move_bps / fwd_bps`
Edge cases:
- if `fwd_bps <= 0`: multiplier is undefined → display `--` and show validation.

#### Move up/down (Live Stats)
- `move_up_bps = points_to_bps(high_since_ref - ref_price)` (>= 0)
- `move_down_bps = points_to_bps(low_since_ref - ref_price)` (<= 0)

#### Outlier rule (default)
Default: **P5/P95 trimming**
- When excluding outliers: drop values `< P5` or `> P95`.
- Stats are computed over the post‑trim sample.

#### Surprise z-score (bucketing basis)
Per event instance, for headline or a component:
- `surprise = actual - consensus`
- `z = surprise / consensus_stddev`
Rules:
- If any required value is missing for an event instance, that instance is excluded from **bucketized** views (but still included in No-filters/All-events mode).
- **Default std dev values** for UI inputs are sourced from `economic_events.db.consensus_std_dev` (per event/component).
  - If `consensus_std_dev` is missing for a component, default to a **reasonable fallback based on the consensus series spread** (e.g., population std dev of historical `consensus` values for that event/component).
  - If both are missing, fall back to a component-level hardcoded default in config (documented in `/api/event_types`).

#### Headline-only σ bucketing (Boxplot X-axis = headline)
Given headline `z` and bucket width `w_sigma` (default `0.5`):
- `bucket_idx = floor(z / w_sigma)`
- Bucket edges are aligned so 0 is a boundary:
  - bucket represents \([bucket_idx*w_sigma, (bucket_idx+1)*w_sigma)\)
- Label example: `[-1.0σ, -0.5σ)`

#### Low/Medium/High (L/M/H) mapping (for headline+components mode)
Given `z` and threshold `thr_sigma` (default `0.5`):
- `Low` if `z <= -thr_sigma`
- `High` if `z >= +thr_sigma`
- `Medium` otherwise

#### Headline + components combination bucketing (Boxplot X-axis = headline_plus_components)
Given:
- headline `z_h`
- component z-scores `z_c1..z_ck` for selected components
Compute:
- `headline_LMH = LMH(z_h)`
- `comp_i_LMH = LMH(z_ci)`
- `bucket_key = (headline_LMH, comp1_LMH, comp2_LMH, ... compk_LMH)`
Notes:
- All possible combinations are valid buckets; number of buckets is \(3^{1+k}\) (headline plus k components).
- UI label format: `H:<LMH> | <CompKey>:<LMH> | ...` (e.g., `H:High | UER:Low`).
- Guardrail: if `k > max_components_in_combo` (from `/api/event_types.bucket_schemes_by_type`), the UI must reduce deterministically (see Boxplot panel spec).

#### “User bucket” highlight (★)
If the user enters headline (and component) inputs in Input Controls:
- compute the user's `z` (or LMH) using the same rules above
- compute the corresponding bucket key
- highlight that bucket with `★`
If user inputs are incomplete (missing consensus/stddev/actual where required), do not show `★`.

#### Expected rally / selloff + rally rate + 0bps percentile
Given sample `moves_bps`:
- `expected_rally = mean(moves_bps where moves_bps > 0)` (0 if none)
- `expected_selloff = mean(moves_bps where moves_bps < 0)` (0 if none; keep sign negative)
- `rally_rate = fraction(moves_bps > 0)`
- `p0 = percentile_rank(0 within moves_bps)` (ties deterministic, e.g., mid‑rank)

#### Histogram bins aligned to 0 boundary
With `bin_width > 0`:
- `k_min = floor(min_bps / bin_width)`
- `k_max = ceil(max_bps / bin_width)`
- edges: `edge_i = i * bin_width` for `i in [k_min .. k_max]`

If `bin_width` is auto:
- Use **Scott's rule**: `h = 3.49 * std(data) / n^(1/3)`
- Minimum **5 bins**, maximum **50 bins**
- Then apply 0-boundary alignment per edge construction formula above

### Appendix F — Performance targets (make “snappy” testable)
- Cold load:
  - `/api/events`: < 250ms server time (local)
  - first `/api/event_details`: < 500ms server time
- Warm interaction:
  - window/toggle recompute (L2): < 100ms server time
  - drilldown (bin → day list): < 100ms
- Payload discipline:
  - never return all events full paths in one response
  - No‑filters mode must load incrementally or use precomputed stats

### Appendix F.1 — Large-sample interaction contract (No-filters / stats-lines)
When a view requires aggregating across many events (e.g., Price Paths **stats-lines** mode, Distribution Explorer across all events):
- **Do not** fetch N separate `/api/event_details` for large N.
- If sample size \(N \le 50\): UI may lazily fetch per-event details.
- If \(N > 50\): server must serve aggregated results from precomputed `stats.arrow` (or equivalent L2 cached aggregates), so interactions stay within Appendix F warm targets.

Minimum required aggregated payloads (can be implemented as either new endpoints or as optional fields returned by existing endpoints):
- **Price envelope**: mean + P5/P95 (or chosen percentiles) over time for the selected window.
- **Distribution sample summary**: histogram bin counts + the exact stats list required by Distribution Explorer.

- Every panel must implement:
